# 浏览器与搜索引擎合作 / 默认搜索分发调研

日期：2026-08-28\
调研范围：百度、必应（Bing）、搜狗、360 搜索、Google；重点是浏览器地址栏/新标签页的默认搜索分发、搜索 API、站长/内容与广告合作入口。资料优先采用搜索引擎或监管机构的一手页面。

## 结论先行

1. “把搜索框默认指向某引擎”与“购买搜索结果 API”是两种不同合作。前者通常是商务分发协议（流量、品牌展示、质量/安全、结算、数据与审计、区域和期限），公开网页通常只有商务入口，没有可自助注册的统一价目表；后者才有公开开发者文档和 API key。
2. 以 Aira 目前几千用户的规模，最现实的路径是先把产品和流量数据整理成一页英文/中文 partner brief，直接联系各家的搜索/浏览器/商业合作团队，提出**可撤销、用户可选择、按地区/版本灰度**的默认搜索试点；不要先承诺独家或永久默认。
3. 百度、搜狗、360 的公开入口主要面向站长资源提交、内容/特型卡片、广告或联盟变现，并不是“第三方浏览器默认搜索”自助入口。必应提供公开 Web Search API，但必须遵守 Bing 的搜索体验、归因、缓存、广告和隐私要求。Google Custom Search JSON API 页面明确写着对新客户关闭，现有客户需在 2027-01-01 前迁移，因此不适合作为新的全网搜索 API 依赖。
4. 无论是否收费，地址栏查询会把用户输入传给第三方。应在隐私政策和设置中明确搜索提供商、处理目的、可能的日志/个性化、跨境传输（如 Google/Bing）和变更方式；默认值不能暗中锁死，保留手动切换和退出路径。中国用户场景还需按《个人信息保护法》等评估告知、同意、最小必要和委托/独立处理者关系；正式合同应由法务确认。

## 合作模式与谈判对象

### A. 默认搜索分发（需要商务谈判）

浏览器在地址栏、新标签页、搜索建议或预装引导中把某引擎作为默认/候选。常见合同议题（以下是行业实践归纳，不是某一家公开承诺）：

- **流量定义**：有效搜索次数、活跃设备/用户、地区、平台版本、是否包含建议点击及新标签页流量。
- **商业条件**：按有效搜索或广告收入分成、最低保证、结算周期、无效流量/作弊扣除、税务和发票。
- **产品与品牌**：搜索 URL/参数、Logo 和“Powered by”展示、结果页跳转、建议接口、崩溃/不可达时的回退、品牌审核。
- **用户控制**：首次运行选择、设置内切换、卸载/退出、地区差异、更新后默认值是否可变更。将默认值永久写死或静默改掉会带来信任和合规风险。
- **数据与安全**：查询和设备标识的字段、保留期限、双方控制者/处理者角色、跨境传输、未成年人和敏感查询处理、审计与安全事件通知。
- **运营指标**：SLA、延迟、可用性、内容安全/投诉、A/B 试验、版本灰度和终止后的数据删除。

公开文档很少披露这类分发价格；应把“几千用户”换算成月活、每日搜索次数、地区/语言、留存、设备覆盖和预计增长，并说明 Aira 能提供的展示位置、可控灰度和反作弊能力。

### B. 搜索 API（开发者产品，不等于默认分发）

API 适合在 Aira 自己的结果页呈现结果，通常按调用量收费并有严格展示限制。若只是把地址栏重定向到 `baidu.com` / `bing.com`，通常不需要 API key，但仍受对方网站条款、品牌和隐私政策约束；API 结果不能随意缓存、混排或再训练。

### C. 站长/内容/广告合作（可自助注册，但解决的是另一件事）

站长平台可帮助 Aira 自有网站被收录、提交 sitemap、监控索引或获得内容卡片；联盟/广告平台可以变现 Aira 的页面。这些入口不能推导出搜索引擎会为 Aira 提供默认搜索分发合同。

### 浏览器侧的公开“默认值”事实

主流浏览器的官方帮助页把默认搜索引擎作为用户可更改的设置：

- [Chrome 帮助：设置默认搜索引擎](https://support.google.com/chrome/answer/95426)：部分国家/地区要求用户选择默认引擎，且用户可以随时更改；企业管理员也可通过策略管理。
- [Edge 支持：更改默认搜索引擎](https://support.microsoft.com/en-us/edge/change-your-default-search-engine-in-microsoft-edge)：用户可改为支持 OpenSearch 的任意站点。
- [Firefox 支持：更改默认搜索设置](https://support.mozilla.org/en-US/kb/change-your-default-search-settings-firefox)：提供默认引擎、搜索建议等用户设置。

这些页面不能证明某一引擎会给 Aira 报价，但说明 Aira 的设计和谈判材料应把“用户可见选择/随时更改”作为基线，而不是隐藏的强制锁定。

## API 使用的关键限制（以 Bing 为例）

微软官方要求很具体，适合作为 Aira 评估其他 API 合同的检查清单：

- 结果只能用于响应用户直接查询的互联网搜索体验，并提供多个结果、可点击来源和“来自网络”等明显提示。
- 不得复制、存储或缓存响应；连续服务例外：设备端通常只能保留至查询后 24 小时或用户再次查询（取较短），服务器端历史结果最多 21 天且只能展示给原用户，不能响应新查询。
- 不得改写结果内容、删除归因/URL 或无约定地重排排名；不得把 Bing 结果与其他通用搜索、LLM 或广告网络混在同一页面；结果页不得投放非 Microsoft 提供的广告。
- Web/Image/News/Video/Visual 结果需显著 Bing 品牌、Microsoft 隐私声明链接和来源归因；Bing Custom Search 的归因规则不同，应按具体产品合同执行。
- GDPR 场景下，调用方与 Microsoft 是独立数据控制者，各自负责合规；Bing 客户端 ID 必须与认证用户信息不可关联，并按设备/用户稳定复用以维持一致体验（见 [请求头文档](https://learn.microsoft.com/en-us/bing/search-apis/bing-web-search/reference/headers)）。

## 中国场景的隐私/合规工作项

以下是产品和法务应共同核对的事项，不构成法律意见：

1. **告知**：在首次使用和设置页说明默认搜索提供商、会发送哪些查询/设备信息、用途（返回结果、反作弊、统计/个性化）、保存期限、提供商隐私政策链接和切换方式。搜索词可能推断健康、财务、未成年人等敏感信息，不能只写成笼统的“改善服务”。
2. **合法性与最小必要**：按《中华人民共和国个人信息保护法》（全国人大常委会官方发布页：[个人信息保护法](https://www.npc.gov.cn/npc/c30834/202108/7c9af12f51334a73b56d8fe2cc3e95b6.shtml)）评估处理基础、单独同意/撤回、未成年人、敏感个人信息和委托处理要求；不要把 Aira 账户标识、通讯录或与搜索无关的浏览历史附带给引擎。
3. **第三方关系**：合同中明确 Aira 与引擎是独立处理者还是委托处理者，查询日志归属、广告/个性化用途、分包商、删除与审计、事件通知和终止后的清理。API 供应商的独立控制者条款（如 Bing/GDPR）不能自动替代 Aira 的告知义务。
4. **跨境与地区**：Google/Bing 等可能涉及境外服务；按用户所在地、数据出境规则、网络可达性和企业合规评估，必要时按地区提供不同引擎或仅跳转其公开网页。不要用代理或隐藏参数规避提供商区域/出口限制。
5. **用户控制与可观测性**：默认引擎可在设置中切换，显示当前实际使用的引擎；回退/不可用策略应透明、可关闭，不应静默永久改默认。记录聚合后的调用量、错误率和结算指标时避免保存原始搜索词。

## 建议的下一步（面向几千用户的试点）

1. 准备一页 partner brief：公司/应用主体与合规资质、月活和日均搜索次数、地域语言、设备平台、地址栏/新标签页位置、预计增长、当前引擎、可提供的品牌位和灰度能力。
2. 先分别走百度搜索商业合作、腾讯/搜狗资源合作、360 搜索站长/商务、Microsoft Bing 商务/合作和 Google 相关全网搜索替代方案联系人；站长/广告平台注册只作为并行的内容或变现验证，不宣称已经获得默认分发资格。
3. 对每家提出非独家 4--8 周小流量试点：用户可选、地区/版本灰度、明确展示品牌和隐私链接、按有效搜索结算、无效流量审计、SLA 和退出时恢复原设置。要求对方书面确认是否允许地址栏默认、搜索建议、结果页跳转、缓存/日志以及第三方广告。
4. 在收到条款前，Aira 只保留公开搜索 URL 的用户选择功能；不要把供应商 API key 放进客户端，也不要为了“谈合作”采集超出搜索必要范围的个人信息。

## 资料边界

公开页面能确认产品入口、技术限制和用户设置行为，但没有公开百度/搜狗/360 面向小型第三方浏览器的统一默认搜索分发报价或标准合同。商业条款、地区可用性和联系人应以对方书面回复及最终合同为准。
