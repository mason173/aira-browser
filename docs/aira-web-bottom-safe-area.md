# 网页底栏防遮挡（实验室）

入口：设置 → 实验室 → 网页适配 → 网页底栏防遮挡（PC / 大屏壳的实验室不显示这一组，见下）。`webBottomSafeAreaEnabled` 默认 `false`，旧设置或非布尔值也回退为关闭；切换到基本模式时关闭。修改其他实验室设置、代理配置或执行旧版本迁移时保留这个值。

PC / 大屏壳（`isLargeScreen`）下 `SettingsDetailViewModel.filterLargeScreenHiddenGroups()` 会跳过整个"网页适配"组：这项只对手机壳的悬浮底栏有意义，大屏壳的 `BrowserWebBottomSafeAreaCoordinator` 本身不生效（`eligible` 已排除 `isLargeScreenShellFamilyActive()`）。隐藏只影响设置界面，已保存的 `webBottomSafeAreaEnabled` 值不变，回到手机壳后按原值继续生效。

## 行为与边界

- 仅在开启功能、浏览器页面可见、手机布局的普通 HTTP(S) 网页中观察。默认关闭时不注入运行时；关闭已开启的功能会执行一次清理脚本，移除观察器、监听器、定时器和文档缓存。
- 检测服务只读取 DOM、样式和几何信息，不改网页样式，不持久保存网址或页面数据。页面内使用事件监听和 MutationObserver/ResizeObserver；静止且没有待处理变化时没有定时任务。
- 每次检测最多从底部 20 个点向上检查 80 个祖先元素；只有通过形状和定位筛选的候选底栏才遍历子元素，每个候选最多 96 个元素，所有候选合计最多检查 192 个节点。检测有 4 ms 的协作式软预算，超预算返回 `deferred`，保留当前留白，延迟 500 ms，单次失效最多补试两次，随后等待下一次真实事件。DOM/样式单次读取不可中断，软预算不是硬实时耗时保证。
- 候选需覆盖至少 65% 网页宽度，高度 28–140 CSS px 且不超过视口 24%，底边距视口底边不超过 32 CSS px。要求 `fixed`，或带底部约束且已贴底的 `sticky`。
- 候选内需要至少两个横向分开的可点击目标；支持链接、按钮、ARIA Tab/按钮/链接、内联点击入口，以及带 `cursor:pointer` 的框架元素。使用命中测试排除被遮住的目标，排除对话框。
- 普通页脚、单个悬浮按钮、顶部导航和大型弹层不触发。没有可识别点击语义的自定义控件、跨域 iframe、封闭 Shadow DOM 和非标准底栏可能漏检；不能保证识别所有网站或广告。

## 稳定性与布局

`WebBottomSafeAreaScriptService` 在当前文档内安装可暂停、恢复和销毁的运行时。页面可见/加载完成时通过现有 `runJavaScript()` 通道幂等安装；初次有效检测无需等待原来的第二次 1 秒采样。已准备好的页面通常在约 120 ms 的合并窗口后开始验证，这不是网络加载或主线程繁忙时的延迟保证。

事件处理分为两层：

1. `MutationObserver` 回调只收集变化，最多查看 48 条记录、保留 16 个新根节点，不读取计算样式或几何。无已知底栏时，在合并任务中最多查看 64 个新增元素的标签、class/id/role/style 提示，再决定是否进行底部命中检查。候选提示包括 nav/footer、链接/按钮及 bottom/tabbar/fixed/sticky 等；提示不是命中结论，仍需通过几何与可点击规则。
2. 找到底栏后缓存实际元素，优先局部验证；普通新闻列表的无关变化直接忽略。底栏及其祖先属性变化、底栏子树变化、移除、尺寸变化、样式表变化、相关动画结束、视口/加载/路由事件请求重新验证。确认命中即可启用，已有底栏消失需间隔至少 300 ms 再确认一次，避免框架替换元素时闪烁。

变化合并窗口为 120 ms，几何检测之间至少间隔 300 ms。页面捕获嵌套滚动、触摸和 wheel 事件，只记录交互时间；**滚动本身不启动检测**。手指按住和最后一次输入后 650 ms 内不进行几何检查，待处理的变化在安静期再验证。原生协调器也保护晚到的桥接消息，避免滑动中调整视口。软预算无法抢占已经进入的单次样式/布局读取，MutationObserver 事件投递本身也有成本，不能宣称“零性能开销”。

`BrowserWebBottomSafeAreaCoordinator` 不再轮询网页。页面通过已有 `__airaPageBehaviorNativeBridge.onSignal` 发送独立的 `bottom-safe-area` 消息，仅结果改变时发送（暂停恢复后允许重新确认）。消息有长度、类型、文档代次和递增序号校验；消息不会进入媒体观察业务。代次用于过滤旧结果，不作为安全凭证；网页提供的数据只影响有界的本地底部间距。

原生会话按标签、控制器和文档代次记忆结果，页面保存对应的候选元素：

- 设置遮盖浏览器时暂停观察器和工作监听，保留识别结果与留白；返回同一文档时立即沿用，再安静验证。
- 标签管理页是壳内浮层，同样只暂停观察、保留留白，并由 `showTabsSheet` 的变化重新求值，返回网页后观察器和留白一起恢复。留白只在真正占用底边的输入面（键盘、地址栏、阅读器浮层）出现时释放：前者只遮住页面，若一并释放留白，浮层关闭时会触发一次网页缩放回流。
- 切换标签暂停旧标签，返回时复用；关闭标签释放控制器引用和运行时。
- 同 URL 重载、文档开始或控制器替换清除旧结果；同一文档的 URL 变化不直接清空缓存。
- `pagehide`/隐藏暂停；`pageshow`/可见仅在原生仍允许时恢复。文档导航后按 ArkWeb 的新 JS 上下文重新安装。

底栏依据**当前网页视口**底边判断，网页缩短后仍可识别，不能因为避让成功就撤销留白。滚动时保留常态悬浮栏的包络高度，不追随悬浮栏收起动画。

这借鉴广告拦截的增量变化处理、预算和消息去重，但不调用 Rust 广告过滤引擎，也不依赖广告拦截开关。当前规则很少，Rust 无法代替 DOM 布局读取；未来大量站点规则可由 Rust 按站点/class/id 筛选候选，再沿用此处的局部验证与布局控制。

留白取现有悬浮栏常态高度加底部间距，与系统底部安全距离取较大值，再增加 8 vp 点击间距。当前为 68 + 25 + 8 = 101 vp（系统安全区更大时随之增加），不重复累加系统安全区。`BrowserWebViewportCoordinator` 先从原生 Web 宿主区域扣除这段距离，发布缩短后的 `hostHeightPx` 和单独的 `reservedBottomInsetPx`；随后内容高度仍按普通页面的 `hostHeightPx - topInsetPx` 计算。`BrowserWebViewportSurfaceHost` 的整个原生显示区域缩短并裁剪在对应底边，底部留白处在这个区域外。相当于一块更矮的原生屏幕，不向 HTML 注入 padding。固定底栏按缩小后的网页视口重新布局。

顶部沉浸收起/展开继续使用原有的 180 ms `EaseOut` 动画，有无底部留白都走同一条动画执行路径。此前针对底部留白把时长置零的特殊处理已移除，它会造成即时改高的顿挫。导航、全屏和手动策略切换等原本为零时长的动作仍立即生效。

有无底部留白都使用相同的顶部布局与动画规则，不设置专门的 `renderFit`。原先只缩短 Web 子内容、外层仍维持全高的结构已改为整个原生宿主一起缩短，外层裁剪边界也随之收紧，手机 Web 槽明确顶对齐，避免变矮后在全高槽里居中；顶部动画发生在这个底边固定的较矮区域内。底部留白不跟随顶部收起/展开变化。回归将有留白的页面与普通短屏逐字段比较，并验证实际动画回调的时长一致。

底部预留区域由原生遮罩填满，不透出主页。外层背景容器覆盖 `hostHeightPx + reservedBottomInsetPx`，Web 仍只占缩短后的 `hostHeightPx`；遮罩从 Web 宿主底边开始，高度等于预留值，并阻止点击穿透到底下的主页。上下安全区共用 `BrowserWebSafeAreaBackground`，由壳层传入相同的背景色和颜色过渡时长，跟随网页背景及主题变化。

底部留白存在时，浏览器悬浮工具栏立即恢复并保持 `resting` 状态，覆盖当前页面的滚动收起/隐藏策略；不会修改用户存储的全局滚动偏好。根滚动、局部滚动和手势结束都走同一策略，手动 `peek` 恢复为 `low`，已展开的 `middle` 面板保留。留白撤销后恢复原全局偏好。顶部沉浸把这种固定显示的 `low` 工具栏与正在输入/展开的面板区分开：前者允许顶部继续随滚动收起、展开，后者保留原先的可见性约束。

### 滚动反馈防抖补充

取消尺寸插值并不能单独消除抖动：顶部收起仍会让 Web 视口变高。靠近文档底端时，新的最大滚动范围更小，Web 会向后修正 `scrollY`；该回调过去会被当成用户反向滑动，先恢复底部工具栏，再强制显示顶部，形成高度来回变化。

`refreshWebViewportPresentation()` 把前后几何交给既有 `BrowserWebScrollInteractionCoordinator.handleViewportChanged()`。在使用显式高度、宿主高度不变且 Web 高度实际变化时，记录反向高度差作为有限的滚动修正额度，普通网页和有底部留白的网页都适用。随后 650 ms 内，方向与额度一致、累计不超过高度差的根滚动回调只更新上下工具栏的滚动基线，不触发新的收起/展开决策。新手势、导航、壳层隐藏、宿主大小变化会清除额度；不同方向、超过额度的位移立即回到正常手势判定。没有新轮询、JS 扫描或滚动回写。

这是原生回调缺少滚动来源时的有界推断，不是内核提供的“布局滚动”标记。同一个未结束手势在窗口内立即小幅反向，也可能消耗这段额度；因此保持时间/位移上限，并覆盖新手势和较大反向立即恢复的回归。`check-aira-top-immersion-motion.cjs` 通过实际上下工具栏调用顺序和壳层几何回调，复现视口增高后页尾滚动范围钳位。此前保护只在底部避让启用时生效，普通网页回放会出现 `[隐藏, 显示]`；去掉该依赖后，两种页面都只出现 `[隐藏]`。另覆盖分次回调、惯性阶段的修正、页中继续滚动、过期、新手势、超过额度和继续向下滚动，同时检查上下两个方向都保留 180 ms 动画。这些回归证明判定结果，不能替代首滑连贯性和固定底栏跳变的真机视觉验收。

键盘、缩放、页面全屏、阅读器和标签概览等临时状态暂停检测；全屏、原生文档和大屏布局不应用底部留白。文档级记忆仅存在内存中，不把整个网站永久标记为需要避让。设置开启/关闭通过既有实验室设置刷新信号生效。

## API 与验证

ArkWeb 调用沿用项目已有的 `WebviewController.runJavaScript()`。本机 DevEco 官方 SDK `ets/api/@ohos.web.webview.d.ts` 的该方法说明确认：在 UI 线程调用、异步返回 `Promise<string>`，导航后页面 JavaScript 状态不保留。本实现不依赖跨导航页面状态，也复用已在 HostedWeb 控制器挂载时注册的页面行为 Bridge。官方 SDK 说明 `registerJavaScriptProxy()` 新注册对象要在下一次加载后才可见，因此不在实验开关打开时临时注册新对象或强迫用户刷新页面。Huawei 文档入口：<https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/web-app-component-interaction>（文档站正文为动态加载，API 声明以本机官方 SDK 为核查依据）。

专项检查：

```sh
node scripts/check-aira-web-bottom-safe-area.cjs
node scripts/check-aira-top-immersion-motion.cjs
node scripts/check-aira-bottom-toolbar-sheet-contract.cjs
node scripts/check-aira-toolbar-sheet-dismiss.cjs
```

检测用例在受控 DOM 几何上执行生产脚本，覆盖固定/吸底栏、嵌套点击区域、普通页脚、悬浮按钮、遮挡、缩放、缩小视口后的持续命中。事件运行时用例覆盖静止无扫描、动态出现、合并变更、缓存后的新闻更新、CSS 隐藏/元素移除、局部复查、长按/嵌套滚动/惯性滚动、预算补试上限、隐藏/BFCache 生命周期及关闭后的完整回收。原生协调器用例覆盖设置返回无留白闪烁、标签记忆、同 URL 重载、控制器替换、旧消息拒绝、滚动中晚到消息延后、关闭标签清理；设置用例覆盖序列化后重读和旧设置默认关闭。

覆盖限制：没有有意义标记或点击语义的自定义 div 底栏、纯 CSSOM 改动（无 DOM/尺寸/加载事件）、只在滚动中变为吸底的未知 sticky 元素，以及跨域 iframe/封闭 Shadow DOM 可能漏检。此次优先避免无变化时和滑动中的兜底扫描；不能保证所有站点立即命中。
专项回归验证有无底部留白都保留顶部 180 ms 动画、整体宿主与普通短屏的几何等价、固定显示底部工具栏时顶部仍可独立沉浸、撤销留白后恢复滚动偏好、局部滚动和手势结束保持固定工具栏。保留页尾滚动修正的独立回归，避免把页尾反馈问题等同于动画瞬间跳变。几何模型和脚本用例不能替代 ArkWeb 在实际手机上的逐帧验收；当前改动尚未做设备画面检查。
