# Sync Topology Transitions Are Atomic Across Enabled Domains

Accepted: changing the shared Primary Sync Source is an atomic Sync Topology Transition across every enabled Sync Domain. Aira preflights the target provider and completes the necessary bookmark and personalization initialization/merge work before committing provider roles; if any enabled domain fails, the previous primary/backup topology remains authoritative. Suspended domains do not participate or block the transition. After a successful transition, only the Primary Sync Source changes; existing explicitly enabled Backup Sync Sources remain enabled, while the former primary is not automatically added as a backup. Its remote data and provider configuration remain until the user explicitly selects or removes them. A retained backup that lacks credentials on the current device does not block the transition: it is marked unavailable locally, may retain older provider metadata, and catches up on the next authorized backup write after credentials return. This keeps backup enablement explicit while preventing settings from claiming one shared primary while different domains still depend on different providers.
