# Backup Sync Sources Are Write-Only During Routine Sync

Accepted: synchronization has one authoritative Primary Sync Source, while the user may explicitly enable either or both remaining configured providers as Backup Sync Sources. Choosing a primary never enables or uploads to the other providers automatically. Routine automatic sync reads, merges, and writes through the primary source first, then writes the resulting state of each enabled Sync Domain to enabled backup sources; it never imports backup-source changes automatically. Backup Initialization may inspect whether existing Aira data is present, but it must not merge that data or overwrite it silently: an empty target can be initialized directly, while a non-empty target requires explicit replacement confirmation or a separate recovery flow. Disabling a backup suspends future writes without deleting its remote history; re-enabling resumes directly only when Aira verifies the same known backup lineage, otherwise initialization confirmation is required again. A healthy and current backup can be promoted without re-merging; the former primary is not automatically retained as a backup, while stale, failed, or unknown backups must enter recovery instead. If primary sync succeeds but a backup write fails, the domain remains successfully synced and enters a Degraded Backup State for that provider; Aira retries without rolling back primary data, disabling the backup, or switching sources. This avoids multi-provider conflict loops and means cross-system live bookmark sync through Aira Cloud is active only when Aira Cloud is the primary source, while an Aira Cloud backup remains a recovery copy.
