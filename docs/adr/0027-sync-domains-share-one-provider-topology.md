# Sync Domains Share One Provider Topology

Accepted: bookmark sync and Personalization Sync remain separate data domains with isolated payloads, merge rules, independent enablement, status, and failures, but they share one user-configured Primary Sync Source and set of Backup Sync Sources. Users may enable either domain alone, both together, or neither. Disabling a domain creates a non-destructive suspension: it stops that domain's reads/writes without clearing provider configuration, deleting local/remote data, or affecting the other domain; re-enabling resumes through the normal non-destructive initialization rules. Remote deletion is a separate explicit dangerous action. The settings surface therefore asks users to choose providers once and lets the Personalization Sync row manage only whether and which personalization items participate. This avoids duplicating provider activation, readiness, Pro entitlement, switching, recovery, and backup state across two domains while preserving strict data separation.
