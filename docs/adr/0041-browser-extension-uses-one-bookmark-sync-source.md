# Browser Extension Uses One Bookmark Sync Source

Superseded by ADR 0047. The extension still has exactly one locally selected Bookmark Sync source, but it no longer follows an App-owned Primary Source or account-level topology. Each extension installation independently selects and initializes Aira Cloud or WebDAV within the current Sync Generation.

Accepted: the Aira browser extension has exactly one active bookmark sync source, selected as either Aira Cloud or user-provided WebDAV, and never manages a Backup Sync Source. The selected extension source must be the App-owned Primary Sync Source; when provider metadata or server policy shows otherwise, the extension pauses bookmark sync and asks the user to change the topology in the App. The extension never initializes, promotes, demotes, or otherwise changes provider roles, and never reads a Backup Sync Source as if it were primary. A topology-verified WebDAV snapshot whose ordinary bookmark partition is empty may be seeded from the computer, but a WebDAV location with no Aira sync state or topology must first be initialized by the App. WebDAV is available without an Aira Account Session or membership; Aira Cloud requires an Aira Account Session, Pro access, and server enforcement of its allowed provider role. Switching sources preserves the old remote data and its provider-specific baseline but stops every read and write until the user explicitly selects it again. The phone App remains the sole owner of topology changes, backup initialization, routine backup writes, degraded backup state, promotion, and recovery. This deliberately trades immediate extension-to-backup propagation for a smaller and less error-prone extension sync flow, and supersedes ADR 0030 only for the extension's provider scope.
