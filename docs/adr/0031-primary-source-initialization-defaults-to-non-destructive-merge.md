# Sync Provider Initialization Defaults To Non-Destructive Merge

Accepted, amended by ADR 0047: first initialization of a Sync Domain against the device's selected Active Sync Provider does not ask ordinary users to choose among merge and destructive replacement strategies. If both sides are readable, Aira applies the Domain's non-destructive merge rules: bookmark conflict/history semantics for Bookmark Sync and per-item merge semantics for Personalization Sync (`主页收藏` plus Common Settings). A confirmed empty current-generation remote is seeded from current local state; unknown, preparing, foreign-account, or incompatible remote state blocks initialization instead of being treated as empty. Whole-device or whole-remote replacement is not part of the current Sync Experience, so selecting a provider never silently discards data.
