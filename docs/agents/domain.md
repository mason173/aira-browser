# Domain Docs

This is a single-context repository. Engineering skills consume the root domain glossary and the root architectural decision directory.

## Before exploring

- Read `CONTEXT.md` at the repository root and use its canonical domain language.
- Read the ADRs in `docs/adr/` that touch the area being changed.
- If a required file is absent, proceed silently; create domain documentation lazily only when a term or decision is actually resolved.

## Vocabulary and decisions

Use glossary terms in issue titles, specs, tickets, tests, and architecture proposals. Avoid synonyms that `CONTEXT.md` explicitly rejects. If work contradicts an ADR, surface the conflict explicitly instead of silently overriding it.
